# Oura integration, PR 1: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans (inline, as the user asked) to work through this plan task by task.

**Goal:** Connect an Oura ring per user, sync its daily data, and show it in Settings, the Daily log, Home and the session screen.

**Architecture:**
- `app/utils/oura.py` is the only code that talks to Oura (OAuth and v2 usercollection).
- `app/utils/oura_sync.py` refreshes tokens and upserts `oura_daily`, with network calls outside `write_tx`.
- `app/routes/oura.py` holds connect, callback, sync, disconnect and today.
- Pages read `oura_daily` through one helper.

**Tech stack:** FastAPI, aiosqlite (SQLCipher), httpx, itsdangerous, Jinja, vanilla JS.

**Spec:** `docs/superpowers/specs/2026-10-11-oura-integration-design.md`

## Global constraints

- Scope `daily` only.
- Redirect URI: `{PUBLIC_URL}/oura/callback`.
- Endpoints: authorize `https://cloud.ouraring.com/oauth/authorize`, token `https://api.ouraring.com/oauth/token`, revoke `https://api.ouraring.com/oauth/revoke`.
- Tokens:
  - never sent to the browser or logged
  - a refreshed refresh token is persisted before any other use; one refresh at a time per user (`asyncio.Lock`)
- `write_tx` bodies: database statements only, never `await` the network inside.
- Typed values always win: the Daily log pre-fill touches only empty fields, and no `daily_logs` row is created automatically.
- DESIGN.md: ink numbers, `.num`, no new colours, no text under 13px, sentence case.
- Readiness band words: ≥85 Optimal, 70–84 Good, 60–69 Fair, <60 Pay attention.
- Integration off unless both `OURA_CLIENT_ID` and `OURA_CLIENT_SECRET` are set.

### Task 1: Oura client (`app/utils/oura.py`)

**Files:** create `app/utils/oura.py`; test `tests/test_oura_client.py`.

**Produces:**
- `is_configured() -> bool`
- `authorize_url(state: str) -> str`
- `redirect_uri() -> str`
- `async exchange_code(client, code) -> dict`
- `async refresh(client, refresh_token) -> dict`. Both return `{access_token, refresh_token, expires_at}`, with `expires_at` as an ISO local time string.
- `async revoke(client, access_token) -> None`
- `async fetch_days(client, access_token, start: date, end: date) -> list[dict]`. Each dict has `day`, `sleep_score`, `readiness_score`, `sleep_hours`, `hrv_ms`, `resting_hr`, `steps`, `active_calories`, `temp_deviation`.
- Exceptions: `OuraAuthError`, `OuraUnavailable`, `OuraError`.
- `band(score) -> str | None`

Tests (`httpx.MockTransport`):
- authorize URL params
- code exchange
- refresh rotation
- merging the four endpoints per day, with the `long_sleep` period chosen and seconds converted to hours
- 401 → `OuraAuthError`; 5xx, timeout and 429 → `OuraUnavailable`
- band edges

### Task 2: Storage and sync (`app/db.py` migrations, `app/utils/oura_sync.py`)

**Files:** modify `app/db.py` (`_MIGRATIONS`); create `app/utils/oura_sync.py`; test `tests/test_oura_sync.py`.

**Consumes:** Task 1.

**Produces:**
- `async sync_user(conn, client, uid) -> str` returns "ok", "reconnect", "unavailable" or "not_connected".
- `maybe_sync(conn, client, uid)`: fire-and-forget when `last_sync_at` is older than 30 minutes, with an in-flight guard.
- `async today_for(conn, uid) -> dict | None`: the latest `oura_daily` row (today or the most recent day).
- `async day_for(conn, uid, day) -> dict | None`
- `async connection(conn, uid) -> dict | None`, without tokens.
- `async save_tokens(conn, uid, tokens)`
- `async disconnect(conn, client, uid, keep_data: bool)`

Tests:
- the first sync backfills 90 days
- the next sync re-fetches from `last_day - 2`
- an expiring token is refreshed, the new refresh token is stored, and the old one is never reused
- 401 → `needs_reconnect=1`
- 5xx → `last_error` set, existing days kept
- upsert idempotence
- user isolation
- disconnect with and without keeping data

### Task 3: Routes and lifespan (`app/routes/oura.py`, `app/main.py`)

**Files:** create `app/routes/oura.py`; modify `app/main.py` (include the router; a 6-hour loop task in the lifespan, cancelled on shutdown; expose the shared client to the Oura routes); test `tests/test_oura_routes.py`.

**Produces:**
- `GET /oura/connect` → 302 to Oura, with a signed `state` (itsdangerous, salt `oura-state`, max age 600 s) carrying the uid and a nonce stored in the session-bound set.
- `GET /oura/callback?code&state` → saves tokens, kicks off the backfill, 303 `/settings?oura=connected`.
  - `?error=…` → 303 `/settings?oura=denied`.
  - A bad, expired or reused `state` → 400.
- `POST /oura/sync` → runs `sync_user`, returns `{status}`.
- `POST /oura/disconnect {keep_data}` → 200.
- `GET /api/oura/today` → `{connected, needs_reconnect, day, readiness_score, band, sleep_score, hrv_ms, resting_hr, sleep_hours, steps}`.

Tests:
- 404 for every route when not configured
- `state` forgery, expiry and reuse
- denial
- a successful callback stores tokens and syncs (mocked)
- another user's `state` is rejected
- disconnect

### Task 4: Settings card and page-load sync

**Files:** modify `app/routes/settings.py` and `app/templates/settings.html`; the `/achievements/unseen` poll calls `oura_sync.maybe_sync` (cheap: one indexed select when connected); test `tests/test_oura_pages.py`.

Card states:
- **Not configured:** a note; the admin sees the setup steps.
- **Not connected:** Connect, and one line on what is read.
- **Connected:** last sync, Sync now, Disconnect (confirm sheet: keep or delete days).
- **Needs reconnect:** Reconnect.

The `?oura=connected|denied` messages show as flashes.
