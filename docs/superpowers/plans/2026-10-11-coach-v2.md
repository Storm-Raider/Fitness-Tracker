# Coach v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generated routines become real programmes: code builds the split, slots, set/rep/RIR/rest
schemes, loads and progression rules; the model picks exercises from ranked candidates and writes
cues; targets reach the plan view and the workout logger.

**Architecture:** A new pure module `app/utils/coach_program.py` owns the programming logic
(patterns, templates, schemes, skeleton, assembly, target annotation). `app/routes/coach.py` builds
the prompt from the skeleton and calls a stronger Gemini model. Chat and swap reuse
`annotate_targets`. Targets are persisted in `routine_exercises.target_json`.

**Tech Stack:** FastAPI, aiosqlite (SQLCipher), Jinja + vanilla JS, Gemini REST, pytest-asyncio.

**Spec:** `docs/superpowers/specs/2026-10-11-coach-v2-design.md`

## Global Constraints

- Plan model: `GEMINI_PLAN_MODEL`, default `gemini-3.8-flash`, `thinking_budget=1024`. Chat is unchanged.
- One week only, plus a per-exercise progression rule. No pre-filled sets.
- New plan fields are optional: `load_kg`, `rir`, `rest_sec`, `progression`. Old plans must still render.
- UI follows DESIGN.md: no orange text, numbers in `.num`, no text below 13px, weights respect the unit toggle.
- Tests run in the worktree's own `.venv`: `.venv/bin/python -m pytest`.
- Before every commit, check `git status --short`: only intended files are staged.

### Task 3: `coach_program` — patterns, templates, schemes, skeleton
**Files:** create `app/utils/coach_program.py`, `tests/test_coach_program.py`
**Produces:**
- `pattern_of(name: str) -> str`, `COMPOUND: frozenset`, `is_hold(name) -> bool`
- `build_skeleton(rows: list[dict], profile: dict, goal: str, days: int, focus_note: str = "") -> list[dict]`,
  where each day is `{"focus": str, "slots": [Slot]}` and each Slot is a dict
  `{role, patterns, sets, reps, rir, rest_sec, candidates: [name], default: name}`
- `target_for(name, row, role, goal, profile, sets=None, reps=None) -> dict` returning
  `{sets, reps, rir, rest_sec, load_kg, progression}`
- [ ] Tests: pattern coverage of the seeded library; split day counts and distinct days; the requested
  split is honoured; strength has no non-compound slot below 6 reps; load formula and rounding; pain
  filter and fallback; ranking puts the athlete's lifts first; fatigued Day 1 rotation;
  session-length trim; feedback/wellness set adjustments; progression strings (loaded, dumbbell,
  bodyweight, hold, stalled).
- [ ] Implement, run, commit.
